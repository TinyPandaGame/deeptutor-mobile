# 客户端版本规则

从 `v0.3.1` 起统一使用纯数字 `vX.Y.Z`，不再增加 preview 后缀。

- 同一 DeepTutor 官方版本下，修复问题或迭代客户端：`Z + 1`。
- 适配并验证一个新的 DeepTutor 官方发布版本：`Y + 1`，`Z = 0`。官方改动的是主版本、小版本还是修复号，都按这条客户端规则计数。
- `X` 保持不变；产品大版本另行决定。
- 官方新增提交、检查到更新、重新构建同一版本，不自动增加客户端版本。仍先适配、测试，再发布到本客户端仓库。

当前源码：客户端 `0.4.0`，适配官方 `1.7.2`，并保留 `1.7.1` 接口回归。后续自身修复为 `0.4.1`；下一次适配官方新版为 `0.5.0`。已发布 Android 安装包仍为 `0.3.3`，iOS 工程仍为 `0.3.2`，安装包版本与源码版本分别标注。

维护命令：`node scripts/bump-version.mjs fix`，或 `node scripts/bump-version.mjs upstream 1.7.2`（示例版本号）。命令同步 package 与 lockfile；`package.json` 的 `deeptutorCompatibility` 单独记录适配的官方版本。

客户端展示和 GitHub/OTA 使用 package 版本。原生基础版本与构建号只在需要新原生运行环境时调整；单纯 JavaScript 修复保持原生指纹，以便已有安装包收到兼容 OTA。不能修改指纹规则来强行让不兼容安装包热更。新原生环境需要全量安装包，iOS 自行签名的安装需分别核对 runtime。
