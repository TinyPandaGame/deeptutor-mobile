# 手机端服务扩展（个人模型与对话清理）

验证目标为 **DeepTutor 1.7.1 / 1.7.2 / 1.7.4**；未知版本仍拒绝加载。普通账号无需提升为管理员，即可填写自己的 API Key、发现模型、保存配置及选择对话模型。未安装扩展时，客户端仍能切换官方 `/api/settings/llm-options` 返回的模型，并明确提示个人配置接口未安装。

## 安装边界

将 `mobile_models` 包放到 DeepTutor 服务进程的 Python 导入路径，在创建 FastAPI `app` 后、启动服务前执行：

```python
from mobile_models import install
install(app)
```

Docker 应使用只读代码挂载或自建镜像，保留既有数据卷和启动配置。先备份入口代码，完成离线测试与启动检查，再重启对应服务；不要覆盖已有 compose 配置。本仓库不包含部署地址、账号、Key、签名材料或学习数据。

扩展对上游个人模型读取函数安装一层兼容适配，保留官方 OAuth 的检查，并在请求作用域内加入当前账号的 API-key 模型。上游版本变更必须先重新验证；版本不匹配时拒绝安装，不能直接跟随官方更新上线。移除初始化调用并重启即可撤回代码，不需迁移学习资料。

## 数据与权限

- 使用官方认证依赖和当前账号上下文。客户端不能指定他人的用户 ID 或共享 provider 引用。
- Key 存于 `data/system/user-secrets/<owner>/mobile-models.json`，位于学习沙箱不挂载的目录，原子写入文件权限为 0600。
- 列表仅返回 `has_key`，不回传 Key。客户端表单在内存使用输入内容，不写入偏好、学习记录或更新配置。
- 空 Key 保留已有 Key；修改 API 地址或服务商必须重填 Key，避免将旧密钥发送到新地址。
- 模型发现不提交推理请求，返回结构化状态，客户端不会把认证失败当作连接成功。
- 个人接口要求公开可达的 HTTP(S) API 地址，拒绝嵌入凭据、查询参数和解析为本地/私网的地址。私网模型部署继续由服务器管理员配置。
- 只扩展个人对话 LLM。知识库向量、搜索、TTS/STT、图像/视频服务仍使用服务器原有配置。部署管理员继续管理共享设置。

地址校验只检查当时的 DNS 结果，不是完整的出站网络隔离。部署时应使用 HTTPS 模型接口并限制服务进程的出站网络，不能将它作为面向任意注册用户的安全代理。密钥以受文件权限保护的明文存于服务端，部署管理员可读取；客户端用户必须信任该服务器。更多边界见[安全说明](../docs/security-review.md)。

## 接口

所有路径位于 `/api/mobile/models`，使用现有 DeepTutor 登录令牌：

| 方法 / 路径 | 用途 |
| --- | --- |
| GET `/api/mobile/models` | 当前账号的脱敏配置、服务商选项及默认选择 |
| GET `/options` | 官方授权模型与个人模型合并后的选择列表；个人默认优先 |
| POST `/discover` | 使用表单新 Key 或该账号已存 Key 查询模型列表 |
| POST `/profile` | 创建/更新一组服务商、Key 和模型；模型 ID 稳定保存 |
| POST `/default` | 设置当前账号默认模型 |
| DELETE `/profile/{id}` | 删除当前账号指定配置；已保存对话与资料不变 |

当前配置是账号级，不按同一账号内工作区复制 Key。不同服务端、不同账号的数据分别保存。删除模型后打开旧聊天会要求重新选择，不能悄悄改用另一种模型。

## 验证

在隔离环境安装 `deeptutor[server,providers,reading]==1.7.4`（或已验证的 1.7.1 / 1.7.2），以及同版本 `deeptutor-questions`、`httpx`、`python-multipart`。测试还需要 Node 24 执行客户端实际的配置生成函数。随后执行：

```bash
python server/tests/test_mobile_models.py
python server/tests/test_upstream_contracts.py
python server/tests/test_conversations.py
python server/tests/test_chat_study.py
```

测试创建隔离临时 home，使用 HTTP TestClient，不启动本地 DeepTutor 学习后端，也不读真实学习资料或密钥。覆盖双账号权限隔离、脱敏、留空/替换、下一次运行时配置解析、模型发现、默认选择/删除和无登录拒绝。

Android 交互模拟：`npm run mock -- --base-port 8896 --user-models`，演示账号 `demo` 或 `other`，密码 `demo-pass`。仅 `fixture-key` 开头的模拟 Key 返回成功；无外部请求、无真实模型。模拟结果不能代替实际 VPS 推理验收。


## 保留错题的彻底删除（客户端 0.4.4）

更新整个 `mobile_models` 包（包括 `conversations.py`），沿用已有 `install(app)` 入口；该增强仍只支持已经过契约测试的 DeepTutor 1.7.1 / 1.7.2 / 1.7.4 和本地磁盘附件存储。客户端升级并不自动部署服务器扩展。

- GET `/api/mobile/conversations/capabilities`：确认版本化删除能力。
- DELETE `/api/mobile/conversations/{session_id}`：在当前登录账号/工作区中取消活动任务，保留错题照片，然后在同一个 SQLite 事务中删除聊天及多级追问的真实消息/轮次记录。错题原 ID、分类关系、作答记录保留，关联会话置空。
- POST `/api/mobile/conversations/cleanup`，正文 `{"session_ids":["…"]}`：重试已删除会话的附件清理。只有本扩展创建的清理凭据允许删除存在的目录；拒绝活动会话、路径穿越、符号链接及任意错题目录。不允许指定其他账号或工作区。

原版删除会移除聊天附件目录，其中可能仍有错题照片。因此本扩展将错题照片复制到独立目录、核对字节并更新原错题的图片引用后再清理；不在网络上抓取外部照片 URL。删除结果单独返回 `cleanup_complete`，不会把上游吞掉的附件清理错误当作全部完成。手机端同时核对聊天详情已不存在，并清理当前身份的草稿与缓存。未安装增强的服务器明确阻止此项彻底删除，不静默退回可能丢失照片的旧行为。

自动化测试仅使用临时数据库和合成文件，验证物理记录/附件删除、保留错题照片、重试清理、跨身份拒绝、活动任务及磁盘失败。安装到各自服务后仍须单独验收，仓库升级不会自动更新用户的服务器。

### 1.7.4 服务端兼容验证（2026-11-22）

对官方 1.7.4 Python 包运行上述四组测试，共 34 项通过，覆盖个人模型隔离、实际配置解析、语音与会话接口、彻底删除保留错题照片，以及拍照录题协议。另以官方 1.7.1 创建合成账号、密码哈希、工作区、聊天、错题、作答记录和附件，再由官方 1.7.4 读取同一份数据：原记录保持一致，继续删除聊天后错题原 ID、作答记录和附件字节仍保留。

另在一个已有 1.7.1 实例完成备份并升级到官方 1.7.4，确认原账号、学习记录和附件保留。通过当前 0.4.5 客户端请求实现验证了生产 HTTPS 登录、模型列表、真实模型拍照提取、错题保存和重新读取；删除合成聊天后，错题原 ID、作答和照片字节保留，旧聊天与旧附件地址返回 404，未登录及其他账号不能访问保留照片。此项是接口实测，没有进行本轮 Android / iOS 界面或原生操作验收。

以上允许现有服务端扩展在 1.7.4 加载，不代表客户端已接入 1.7.3 / 1.7.4 的全部新增功能。实际部署仍须先备份，核实目标镜像与当前挂载，再进行在线登录、模型调用和数据保留验收。
